# W25Q64 调试档案

## 当前结论

驱动及基础通信路径已实现。擦写可靠性、断电持久化和偶发异常的最终根因尚未完成验证，不能据此认定 Flash 芯片损坏。正常五任务固件默认 `APP_USE_FLASH_CONFIG=0`，使用 RAM 默认配置并隔离 SPI 初始化。

## 驱动和只读诊断

状态寄存器 SR1/SR2/SR3 可读，写使能后验证 WEL；擦除和页编程检查返回值并等待 BUSY 清除，5000 ms 超时避免永久循环。HAL_OK 仅表示相应调用成功，不证明数据语义正确或掉电保存完成。

`FLASH_READ_DIAG_MODE=1` 进入独立只读诊断，先核查 HAL tick，再读取 ID、状态和配置地址。该模式不运行正常五任务业务，也不自动擦写。写测试保留且默认关闭；不能为追求诊断结果而随意开启覆盖现有 Flash 内容。

`FLASH_SPI_CAPTURE_MODE=1` 必须配合只读诊断：主机先启动逻辑分析仪，再通过 UART 发送 `R`，固件等待 50 ms 后执行 100 次、每次 8 字节的读取，间隔 4 ms。完成采集后输出批次、序号、相对时间、HAL 状态和数据，降低采集中 UART 打印对时序的影响。比较同一批次第一个成功参考的有效性；重复值一致不代表该值一定正确。

## 下一轮实验记录格式

每轮保存固件提交和编译宏、供电/复位条件、引脚与分析仪通道映射、采样率、UART 原文、原始捕获文件、解码导出。按 CS 事务序号和读取序号对齐 SPI 与 UART；明确 D3/D4 对应的物理信号，交换通道时保持其余条件不变。

只读复现、受控擦写读回、完整断电后读回分别进行。擦写前备份目标扇区并明确允许覆盖的范围；保留失败样本，单独统计 HAL 错误、ID 错误、数据不一致和首帧异常。A/B 对比只有在实验条件和原始记录齐全后才形成结论。

AI 用于辅助源码检查、日志整理和假设梳理；最终判断以实际信号、代码路径和重复实验为依据。
